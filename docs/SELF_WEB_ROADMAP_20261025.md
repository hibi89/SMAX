작성: 2026-10-25 KST · 상태: 사용자 **전략 승인 / WEB 기능 미개발**

## 0. 이번 결론 (다른 과거 가설보다 우선)
- **1차 (실제 개발 2026-10-25 ~ 2026-11-07, 총 14달력일 상한):** SELF 중심. 기존 오프라인/로컬 규칙 기반 AX 템플릿·스마트 검색·챗봇형 구조화 질문·자료 필드 매핑·AI 구축 지침. 수요와 개발 여력이 허용하면 **로컬에서 결과까지 생성 가능한 소형 완성형 처리 1~2종**(CSV 정리, 간단 매출 집계 등)을 검증하되 미검증/미완 기능을 판매 상품에 포함했다고 주장하지 않음. 로컬 UI, 홈페이지 10종 쇼케이스, Windows/브라우저에서의 실제 작동 확인과 크몽 상품 등록 준비가 우선.
- **2차 (1차 제품 검증 이후 별도 착수 결정):** **WEB 유료 완성형**. 고객이 회원/구매권한 인증 후 전용 업무 프로그램 페이지에서 버튼만 누르고 곧바로 결과를 받음. 고객이 코딩, n8n, Python, GitHub, API 인증 설정을 직접 할 필요가 없는 **웹 내부에서 완결되는 업무 유형**부터 전환. 모든 템플릿을 WEB으로 강제 변환하지 않음.
- **GUIDE:** SELF 구매자의 막힌 지점을 **문자/비동기 학습 안내**하는 별도 선택 상품(희망가 +5만원). 별도 구축 대행/전화/원격 PC 조작이 아님.

- **WEB 가격, 갱신·사용 기간, 템플릿별 판매/묶음 요금, 고객별 호스팅 정책, 정식 론칭일 모두 미확정.** SELF 희망가 5만원 + GUIDE 5만원 목표만 계승.

## 1. 고객 경험 — 같은 템플릿, 서로 다른 제공 형태
| 구분 | SELF (1차) | WEB (2차) |
|---|---|---|
| 고객 행동 | 템플릿을 찾아 업무 규칙·자료 구조를 확인하고, AI 구축 가이드로 직접 설정 | 구매한 템플릿 웹페이지 로그인 → 파일/조건 입력 → 바로 처리/다운로드 |
| 코어 | 로컬 템플릿/검사/설계 엔진, 가능한 일부 업무는 고객 PC 내 직접 처리 | 재사용 가능한 검증된 순수 변환 로직 + 웹용 실행 어댑터 |
| 별도 외부 설정 | 고급 자동화는 고객이 본인 AI·외부 서비스 직접 설정 | **웹에서 끝나는 유형에 한해 불필요**; Gmail/ERP API 권한이 필요한 유형은 최소 1회 인증/외부 연동이 필요하므로 '무설정'으로 판매 금지 |
| 데이터 | 고객 PC 로컬 우선, 회사 원본을 판매자에게 받지 않음 | 가능하면 브라우저 로컬 처리, 서버가 필요하면 별도 개인정보/보안/저장·삭제 설계 |
| 판매/유통 | 크몽 판매 또는 출시 승인된 채널 | 크몽 등 공식 구매 확인 → 사장님 계정에 템플릿 단위 이용권 발급 |
| 검증 상태 | 현재 10종 설계/안내 초안 코드 작성, Windows 독립 프로그램/실사용 검증 전 | **미개발. 인증·요금·보안·서버 없음** |

## 2. 처음부터 지켜야 할 기술적 경계
1. **공통 템플릿 계약**: 템플릿 ID/버전/분야/입력 스키마/출력 스키마/질문/변환 규칙/검증/보안 주의/교육 가이드를 프론트 화면이나 특정 배포 환경에 직접 결합하지 않음.
2. **템플릿 지원 수준**과 **판매 가능 형태**를 구분: `DESIGN_DRAFT`(가이드 초안) → `LOCAL_TESTED`(SELF 실제 검증) → `WEB_ELIGIBLE`(웹 서비스 전환 후보) → `WEB_TESTED`(웹 입력·처리·다운로드/보안 검증) → `WEB_SALE_APPROVED`(별도 판매 조건 승인). WEB 라벨/구매 버튼은 실검증·판매 승인 전 비활성.
3. **실행 경계**: `templateId + validatedInput + userConfirmedMapping` → `result + warnings + auditSummary` 형태를 목표로 **순수 로직 함수** 분리. 외부 시스템 쓰기/발송/결제/계정 연결을 기본 엔진에 섞지 않음.
4. **공개 홈페이지와 유료 실행 코어 분리**: 무료 사이트에서는 템플릿 탐색, 설명, 합성 예시/미리보기, 템플릿 제안 등만 제공. 유료 SELF 소스/완전 실행 패키지, WEB 서버측 제어 로직, 비공개 사업자료를 퍼블릭 정적 번들에 포함하지 않음. 현재 `site/core.mjs`와 `site/app.mjs`에 동작하는 코드가 있으므로 **그대로 공개 배포 시 일부 유료 기능이 무료 노출된다는 위험을 P9 공개 배포 차단 게이트로 등록**. 1차 출시 준비 중 무료 미리보기와 유료 로컬 배포 경계를 실제 소스 기준 검수할 것.
5. **고객 데이터 보호**: SELF는 로컬 실행 및 고객 승인 없는 네트워크 호출 0 원칙. WEB을 도입할 때는 사용자별 접근·데이터 분리, 개인정보 처리방침/필수 정보·보관기간·삭제·운영 로그, 저장/전송 암호화, 최소 수집, 서버 또는 브라우저 연산 구분 필요. 회사 자료 공유·업로드 기능을 현재 쇼룸에 임의 추가하지 않음.

## 3. WEB 무단공유 방지: 2차에서만 구현
- 웹 주소를 비밀로 숨기는 방식 **금지**. **구매 확인된 고객 식별자 + 템플릿 단위 서버측 권한(entitlement)**을 요청할 때마다 검사.
- 권장 흐름: `크몽 등 공식 결제 완료 수동/검증 등록 → 소유 이메일에 초대 → 로그인/일회용 인증 → 구매한 templateId + 유효기간 확인 → 서버 처리 API 승인/거부 → 감사 기록`.
- **로그인=구매권한 아님.** 인증(누구인가)과 인가(어떤 템플릿을 쓸 권리가 있는가) 분리.
- 가입 이메일 공유 방어는 세션 만료/회수·합리적 동시세션 관리·비정상 사용 제한 등 보조 장치. **계정/인증번호까지 공유하면 100% 방지 불가능**; 과도한 기기 지문수집을 기본값으로 채택하지 않음.
- **핵심 실행 JavaScript를 공용 정적 페이지로 전부 배포하면 복사/우회 가능**. 인증만 붙인 브라우저 측 앱은 무단 재배포 자체를 막지 못함. 유료 서버 검증이 필수인 처리·비공개 로직은 Worker/서버 함수에서 수행하되, 서버로 처리 자료가 오가는 경우 고객 데이터 처리 의무가 생기므로 데이터 위험·서버원가를 평가할 것. WEB 순수 브라우저 기능에 대해서는 부정 이용의 완전 차단을 약속하지 않음.
- Vercel 상업용 운영은 적합한 유료 플랜/약관 확인 필요. Cloudflare는 Static Assets/Workers/D1/Access 등과 연계 가능하지만 실제 요금·허용량·로그인·구매권한 설계는 **2차 출시 전에 재검증**. 도메인/배포/결제 연동/자동 갱신은 현 시점에 만들지 않음.

## 4. 템플릿별 WEB 적합성 판정 예시
| 유형 | 1차 SELF | 2차 WEB 가능성 및 준비 |
|---|---|---|
| 엑셀/CSV 정리 | 구조/매핑·가이드 + 로컬 변환 검증 목표 | **우선 후보**: 브라우저 파일 열기→변환/다운로드; 유료 접근 통제·복제 위험 구분 |
| 매출 집계/보고서 | 집계 규칙/가이드 + 로컬 보고서 검증 목표 | **우선 후보**: 로컬 브라우저 계산 또는 최소 서버 실행 |
| 견적서 초안 | 서식/승인 워크플로 가이드 | 세액·거래조건·PDF 품질·사람 최종 확인 후 웹 완성형 가능 |
| FAQ/리뷰 분류 | 규칙형 교육/AI 핸드오프 | 규칙 기반만 가능하면 웹화; 자유 자연어 AI 답변 제공 시 모델·비용/데이터처리 별도 |
| Gmail/예약/쇼핑몰 자동화 | 외부 AI·n8n 단계별 설계 | 외부 OAuth/API 승인, 동의·권한 및 서비스별 변경 대응 필수. '주소만 누르면 무설정'으로 판매 금지 |
| 사내문서 RAG | RAG 설계 가이드 | AI 검색엔진·문서 권한/서버·임베딩/LLM 필요. 초기 WEB 범위 제외 |

## 5. 개발 단계/금지된 조기 범위 확장
- **D1~D14 (2026-10-25 ~ 2026-11-07 포함): SELF 1차 MVP, 10종 템플릿 가이드와 실제 동작 가능한 작은 기능(여건·검증 결과에 따라 1~2개).** UI/가이드/테스트/로컬 패키징/크몽 상품 등록 준비/홈페이지 시연 검증 우선. 개발 14일 초과 자동 연장 불가.
- **WEB 준비는 문서/모듈 분리/지원단계 메타데이터 수준으로만**. 클라우드 인증·고객 DB·결제 처리·이용권·WEB 실행 API·실고객 서비스 운영 구현 금지 (별도 2차 작업 승인 필요).
- WEB 전환 시작 게이트: (a) SELF 검증 및 공개 범위 확정 (b) 템플릿 중 브라우저 단독 완료 가능한 대상 1종 선정 (c) 실제 크몽·상품 가격/기한/환불/유지보수 조건 확정 (d) 로그인·서버측 인가·공격 테스트 (e) 데이터·저장·원가·중단/환불 정책 승인.
- 작업자 인수인계 시 **WEB이 향후 유료 옵션이라는 사실과 현재 미구현**을 분리 보고해야 함.
