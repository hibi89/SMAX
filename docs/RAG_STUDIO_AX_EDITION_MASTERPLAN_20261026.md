# RAG Studio AX Edition — 통합 상품·시장·기술 마스터플랜

> RAG 전담 저장소: Public `hibi89/RAG_STUDIO` (확인 시점 빈 저장소) | SOVIA: `hibi89/SOVIA_sovereign` (선택형, 구현 상태 별도 확인)
> 이 문서는 2026-10-26 사용자와 논의·채택한 **RAG Studio AX Edition** 상품 결정의 정본이다. 독립형 SMAX의 기존 2026-11-07 출시 게이트를 변경하거나 SOVIA의 로드맵을 강제로 변경하지 않는다.

## 0. 왜 전략을 변경했나
- 종전 `39,000원 문서 RAG` 단독 상품은 무료 AnythingLLM, Open WebUI, GPT4All, NotebookLM 등의 대안과 충분한 차별화가 미확인됐다.
- 방향 전환: **기업 데이터 ZIP/폴더 → SMAX² 분류·표준화 → 로컬 정형 DB + 문서 검색색인 → RAG Studio 혼합 질의·AI 분석 → 출처/근거 포함 대시보드**.
- 장기 철학: 사용자 소유 데이터/실행 환경을 우선하는 Sovereign AX. SOVIA 행동 감사·정책 감사는 **옵션**. 고객별 맞춤 외주/설치 대행/고객 데이터 수령/전화지원 모델을 기본으로 삼지 않는다.
- 기술적 가치는 RAG 기능 수가 아니라 **표준화된 정형 데이터의 정확한 계산 + 비정형 문서의 근거 검색을 결합하는 경험**으로 입증한다.

## 2. 대상 고객 3개 시장 (우선순위는 전략적 적합도, 실구매 통계 순위가 아님)
| 우선 | 주요 구매자 | 입력 데이터 | 대표 구매 성과 | 적합성/조건 |
|---|---|---|---|---|
| **1순위** | **온라인 쇼핑몰·소규모 유통업 사장님** | 매출·주문·상품·재고 Excel/CSV + 상품·환불 문서 | 제품별 매출/재고 KPI, 반품정책 근거 검색, 혼합 질문 | 초기 템플릿·합성 샘플·정답 기준 만들기 용이. 첫 주력 시연 |
| **2순위** | **소규모 제조·기술 서비스업** | 제품 설명서·정비 매뉴얼·품질 기준·발주 이력 | 특정 부품/업무 매뉴얼 검색, 표 데이터와 문서 근거 비교 | 전문용어 검색 품질/문서 파싱 검증 필요 |
| **3순위** | **1인 사업자·컨설턴트·분석가** | 프로젝트별 CSV/문서/보고 자료 | 고객 프로젝트별 지식 검색·분석·보고서 | 로컬 프로젝트 격리/기밀 분리 검증 선행 |

- 초기는 **제품 1개 + 고객 활용 시연 3개**, 업종별 서로 다른 코드베이스 3개를 만들지 않는다.
- 주요 고객은 비개발자이고 제품 제작자도 직접 원격 기술지원을 제공하지 않음. 단순 설치, 명확한 자동진단, 가이드, 도움말·복구 안내를 품질요건으로 둔다.
- 위시켓/크몽의 RAG 구축 호가는 비교 근거이지만 실제 판매량, 구매자 지불의사, 시장 점유율을 입증하지 않는다. 무료 경쟁제품을 실측 비교해야 한다.

## 3. 첫 통합 제품에서 제공할 RAG 사용유형 5개
| 유형 | 고객 시나리오 | 구현 원칙 |
|---|---|---|
| **Document RAG** | PDF/Word/TXT/MD 문서 질문 + 페이지/문단 근거 | 청킹, 키워드·벡터 검색, 근거 누락 시 보류 |
| **Knowledge Base RAG** | 사내 규정·FAQ·매뉴얼 지식베이스 | 문서함/컬렉션/버전·중복 관리 |
| **Multi-Document RAG** | 여러 문서 비교, 차이점 요약 | 문서별 출처 구분·충돌 표시 |
| **Conversational RAG** | 이전 질문을 참조한 후속 질문 | 세션 맥락과 검색 질문 재작성, 환각 평가 |
| **SQL + Document RAG** | DB 집계 결과 + 관련 지침 검색 결합 | **핵심 차별화**, 읽기 전용 검증된 집계 + 인용 결합 |

- 5개가 서로 완전히 독립된 검색 알고리즘은 아니다. 공통 BM25 + Dense(FAISS) + RRF/MMR 하이브리드 엔진 위에 사용자 시나리오/정형 분석을 얹는다.
- 검색 모드는 keyword / dense / hybrid 비교 기능을 제공하도록 계획. 원본 ZIP에 대한 이전 대화 평가에서 hybrid 핵심 로직이 확인됐지만 **현재 `RAG_STUDIO` GitHub에 소스가 업로드/통합/테스트된 것은 아님**.
- GraphRAG, 풀멀티모달, 범용 Agentic RAG, 웹 상시 상담봇, 임의 외부 ERP 쓰기는 초기 범위에서 제외. Corrective RAG와 SQL/DB 외부 연동, OCR/HWPX는 수요/품질 확인 후.

## 4. 전체 아키텍처와 모듈 경계
1. **입력**: 고객 PC의 ZIP/폴더 선택. 확장자/크기/파일 수 제한; ZIP 경로 탈출/압축폭탄 차단; 원본 수정 금지.
2. **SMAX² 필수**: 파일 형식 감지, 업무 템플릿/필드 후보 매핑, 누락/충돌/중복 분석, 사용자 확인 후 표준 출력. 단순 문서 검색은 복잡한 업무 필드 매핑 생략 가능.
3. **정형 경로**: CSV/XLSX → 스키마·품질 기록 → SQLite 데이터셋/설정 메타데이터 → DuckDB 분석용 집계(후보). CSV 변환 시 원본 행과 수정/검토 상태 유지.
4. **비정형 경로**: PDF/DOCX/TXT/MD → 원본/페이지 메타데이터 → 청킹 → BM25/FAISS 인덱스. OCR·암호화/손상 파일은 지원 범위와 미지원 사유 표시.
5. **질의 라우터**: 정형 질문은 검증된 SQL/집계(읽기 전용, 허용 쿼리/표준 KPI); 문서 질문은 검색; 혼합 질문은 **각각 근거 수집 후 결과 결합**. 임의 LLM 생성 SQL을 곧바로 실행하지 않는다.
6. **통합 UI**: 프로젝트/문서·데이터셋 관리, 표준화 미리보기, 데이터/검색 질의, KPI 카드/차트, 출처/계산 근거, 오류·검토 필요 항목.
7. **관측**: 로컬 진단 기본; Studio 모드에서 Grafana/Prometheus; LangSmith는 고객 자격증명·명시적 동의 필요하고 OFF가 기본. 민감 문서·질문이 외부로 나갈 수 있다는 안내 필수.
8. **SOVIA 선택 연동**: 별도 감사 이벤트 계약을 통해 사용 가능한 행위/도구 접근/권한 이벤트만 전달. SOVIA 미설치 시에도 기본 안전 권한·기록은 유지. SOVIA 초기 목표는 사후 감사이며 실시간 차단/완전한 유출 방지는 보장하지 않는다.

### 공통 연동 계약 초안 (아직 코드 아님)
- `AX_DATA_PACKAGE_V0`: schema_version, project_id, created_at, file_manifest(path/type/hash/size/status), datasets(table_schema/field_map/quality/row_provenance), documents(doc_id/page_metadata/index_ref), questions_needing_review[], processing_summary.
- `AX_AUDIT_EVENT_V0`: schema_version, event_id, occurred_at, component(SMAX/RAG/EXEC), run_id, action_kind, actor_scope, target_class, outcome, source_pointer, payload_digest, policy_context. **원문·토큰·암호·프롬프트는 기본 전송/저장하지 않는다**.
- 컨트랙트는 소비/생성 단위테스트를 확보한 후 각 저장소에 별도 배포. 비공개 SMAX 구현을 Public RAG/SOVIA 저장소에 복제 금지.
- 저장소 역할: `SMAX` = 표준화 소스/기존 SELF 전략, `RAG_STUDIO` = RAG/분석/고객 UI 소스, `SOVIA_sovereign` = 감사 코어; 통합 배포 아티팩트는 뒤에 별도 설계. **세 프로젝트 소스 병합 금지**.

## 5. 개발 수순 (기존 프로젝트 일정 불변)
1. 각 프로젝트 독립 MVP 검증: SMAX 실제 CSV 경로/Win UX, RAG 원본 ZIP 소스 확인·안전하게 이식, SOVIA 로컬 감사 MVP. 기존 완료율을 실제 테스트 없이 추정하지 않는다.
2. SMAX 표준화 결과의 **공통 파일 계약**과 fixture/contract test 구현. 처음에는 CSV 1종 + 문서 PDF/TXT, 확장 추후.
3. ZIP/폴더 인제스트 → 지원범위 분류·사용자 매핑 승인 → 로컬 DB/문서 색인 → 읽기 전용 질의 완료.
4. 복합 질문 end-to-end 골드 시나리오, KPI·대시보드 품질, 출처 페이지/원본 행 추적 구현.
5. Studio 추적/성능 리포트, 오류 진단, Windows 셀프 설치·제거·복구·오프라인/저사양 검증.
6. 실제 사용자 셀프 설치 검증, Apache/OSS 라이선스 검토, 개인정보·DB/ZIP 취약성·오류 차단, 무료 경쟁 제품 품질 비교 후 출시 판정.
7. SOVIA 옵션: 기본 세 기능 제품이 검증된 이후에 한정 통합. **SOVIA 개발 일정과 SMAX의 2026-11-07 목표를 AX Edition 때문에 무단 변경하지 않는다**.

## 6. 출시 품질 게이트
- 지원 문서/표 데이터 형식과 파일 한도를 명시; 인식 못하는 기업 데이터를 무조건 표준화/자동 분석한다고 광고하지 않는다.
- 정답 있는 합성 매출/재고 데이터셋 + 문서 세트로 질문 최소 100개 시험(정형 계산 정답률, 근거 일치, 근거 없는 질문 보류, 처리시간).
- 동일 한국어 질문/문서로 AnythingLLM 등 무료 제품과 검색 정확도·출처/설치 난이도 직접 비교; 성능 우위 미확인 시 마케팅에서 우위 주장 금지.
- 서로 다른 Windows PC 최소 3대 자체 설치/재실행·모델 다운로드·제거·복구 확인. CPU-only PC와 RAM 최소치 실측.
- 손상 ZIP, 압축폭탄, 악성 파일명/경로, 조작된 CSV/엑셀 수식, 모호한 통화/세금 필드, 없는 KPI, 암호화/보호 파일 테스트.
- 데이터 외부 전송 0을 로컬 기본 모드에서 검증하고, 선택형 SaaS 트레이싱 데이터 고지/동의 확인.
- 정품·설치 횟수·업데이트·이용권 기간·반품·오픈소스 라이선스·크몽 판매조건 확인. 무조건 무료 고객 기술지원 약속 금지.
- 가격·기능 완성·출시·매출/리뷰/성능은 테스트 및 판매 증거가 없으면 **계획**으로만 표현.
