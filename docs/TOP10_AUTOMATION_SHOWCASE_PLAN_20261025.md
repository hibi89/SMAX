# SMAX 홈페이지 TOP 10 자동화 시연 쇼케이스 — 2026-10-25

> **사용자 신규 결정:** Cloudflare 정적 AX 연구소 홈페이지에서 앞서 조사한 주요 업무 자동화 **TOP 10을 각각 카드/상세 시연으로 보여주고, 실제 가능한 결과와 구축 절차를 가시화**한다. 단순 기능 나열/광고 문구보다 **작동 증거와 고객이 따라 할 수 있는 구체적 흐름**이 우선이다.
> **현 상태:** 설계만 기록. 실코드·실제 업무 자동화·10개 시연 영상·Cloudflare 배포 모두 아직 **NOT BUILT**. TOP 10 숫자는 **전국 실수요 확정 순위가 아니라 먼저 검증할 내부 잠정 우선순위**.

## 1. 제품 범위와 정직한 시연 원칙
- 상업 홈페이지 = **자사 브랜드·기술 쇼룸**, 개인정보/고객 문서 업로드·무료 제품 사용창/서버·문의 폼 없음. **크몽 정식 구매 링크만** 상품 등록 후 노출.
- 실제 SMAX SELF 고객 경험 = 고객 PC 로컬에서 직접 업무 설명·CSV/XLSX/관련 입력 자료 정리 → 공통 업무 스키마/누락 질문 → `AX_BLUEPRINT.json`, `DATA_SCHEMA.json`, `AI_BUILD_PROMPT.md`, `VALIDATION_CHECKLIST.md` → 본인 외부 AI·도구를 사용해 단계별 자동화 구축. 프로그램 자체로 10가지 자동화를 모두 실행/클라우드 연동하는 것이 아니다.
- 홈페이지 카드는 **합성 데이터만** 사용하여 `사장님 요청 → 필요한 자료 → 데이터/업무 표준화 → SMAX 산출물 → 단계별 AI 구축 절차 → 오류 검증`을 보여준다.
- **시연 레이블:** [실제 로컬 엔진 테스트 통과] = 실행 로그와 산출물 재현 가능, [검증된 실제 연동] = 해당 외부 도구를 테스트 계정/샘플 자료로 실제 연결·실행해 확인, [설계/예정] = 구현 예정·아이디어/모션 목업. 메인페이지의 '지원'으로 표시하기 전 기능 수준과 소프트웨어 버전 확인. 현재 10개 모두 초기 기획, 실증된 테스트는 없음.
- 사용자 표현 '실제 가능한 것까지'는 **거짓 시연 금지**, 최소 1~2개 사례는 실제 엔진/합성 입력으로 **전 과정을 재현 가능한 영상·스크린샷**으로 증명하고, 나머지 카드도 10개 템플릿에 대한 요구/입력/산출물/단계 안내를 제시하는 식으로 검증 가능한 범위에서 구현.
- 모든 카드에 **외부 사용 도구(n8n/Google Sheets/이메일 API/LLM/RAG 서비스)와 별도 유무료 비용 및 고객이 직접 설정하는 단계**를 명시. 고객은 자신의 자료 권한·제3자 전송 보안을 스스로 확인.

## 3. 화면 설계 (frontend 브랜치 담당; 사용자 디자인 주도)
- Hero: `SMAX | AX를 누구나 직접 시작하는 방법` + 실제 제품/가상 워크플로 구분된 짧은 모션.
- Showcase: **10개 카드**. 카드 UI는 검색/필터나 로고 남발하지 않고 클릭 시 동일한 단계 패널 열기. 초기 장치/모바일 모두 적절히 반응형.
- 카드 상세: **1. 사장님 질문 → 2. 필요한 예시 자료 → 3. SMAX 구조화 도식 → 4. 파일명/실제 출력 일부 → 5. 외부 AI에 넣는 프롬프트 예시 → 6. 테스트 체크리스트 → 7. 지원 범위/미지원/외부 비용**.
- 멋있게 움직이는 대시보드 애니메이션은 **제품 동작 증명**과 분리. 녹화/캡처에 '실제 실행 / 합성 샘플 / 개념 시연' 배지/캡션을 표기한다.
- 가격 카드: SELF **50,000원**, GUIDE 선택 **+50,000원**, 다만 계약 기간/응대 상한 확정 전 판매 안내에는 미결 문안 게재 금지. 전화·원격 대행·실고객 파일 처리 X.
- FAQ: `고객 데이터가 우리 서버로 올라가나요?` (원칙적으로 로컬, 사용자가 외부 AI에 첨부 시 제3자 전송 별개), `실제 자동화를 대신 설치하나요?` (아니요), `추가 도구 비용이 있나요?` (도구 따라 다름), `AI 없이 다 작동하나요?` (설계/규칙 코어의 필수 유료 AI API 0, 외부 AI 구축 단계는 별개).
- Contact/사업 문의/고객 업로드 없는 Cloudflare **정적** 쇼룸. 링크는 실제 등록된 크몽 상품 페이지만.

## 4. backend와 frontend의 계약
- `backend`: 10개 유형을 나중에 하나씩 바꿔 넣을 수 있는 **데이터 기반 템플릿 스펙**(`id,title,trigger,inputs,outputs,questions,permissions,exceptions,steps,tests,limits`), 구조화 로직, 출력·테스트 담당. TOP 10용 테스트 합성 fixture와 **상태**를 source of truth로 관리.
- `frontend`: 해당 10개 설명/fixture/로그 중 공개해도 되는 결과만 소스에 포함하고 상세 카드/영상/모션 표현. 사용자와 협의 후 배경/로고/색상·전환 설계. main에 병합할 때 각 카드가 **실제 테스트됨/미구현**과 모순이 없는지 검수.
- 10종 모두 **기능 가이드·AI 명령 생성 대상**인 것과, 실제 구동되는 업무 자동화가 10종이라는 주장을 혼동하지 않는다. 특히 외부 Gmail/n8n API 연동·RAG 서버는 SMAX 1.0 배포에 포함되지 않는다.
- 첫 실증 1·4번과 가상 5번(메일)을 중심으로 공통 contract 테스트를 통과시키되 다른 7개도 설계 가이드의 입력/출력/질문 검증 케이스를 만든다. 14달력일 내 남는 기능은 **추후 로드맵**으로 표시하고 실패를 숨기지 않는다.

## 5. 인수 기준(14일 상한은 변경 불가)
- **10개 쇼케이스 카드**가 모두 클릭 가능하고, 각 사례의 요구/자료/설계/단계/보안/한계가 실제로 작성됨(단순 제목 10개 붙이기 금지).
- 제품에서 **검증 완료로 표시한 범위**는 합성 예시를 실제 로컬 엔진으로 처리한 실행 결과·테스트가 있어야 함. 10가지 워크플로가 실제 외부 계정에서 돌아간다는 주장은 수행한 실검증 없이는 하지 않음.
- 1~2개의 핵심 실증 시나리오를 실제 녹화/스크린샷·재현 가능한 입력/출력 fixture로 연결. 미검증은 안내만.
- Cloudflare 실제 외부 게시/유료서비스/상품 등록·브랜드 법적 확인은 별도 출시 승인. `SMAX` 상표 검증 미완, 유사명 리스크 사전 점검. 이번 문서는 승인된 범위의 **기획 업데이트만**, 개발 착수일 미확정.
