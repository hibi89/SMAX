## 0. 결론
- **제품을 완성해 검증할 가치는 충분하다.** 현 단계는 아이디어만 있는 상태를 넘어 로컬 CSV 변환 코드·검증 스크립트·상품 설명을 만들고 있다.
- **'사업이 된다' 또는 '고객이 구매한다'는 아직 증거 없음.** 제품이 작동하는 것과 첫 구매, 월별 반복 수요, 월 150~200만 원 순수익은 서로 다른 검증 단계다.
- **2~3년 기업가치 50~100억 원은 근거 있는 산정이 아님.** 창업자는 엑싯 목표를 철회하고 **염가 AX 대중화·운영 주도권 유지**를 우선했다. 사업성 없는 보조 사업/굿즈/교육 확장으로 성공 가정을 키우지 않는다.
- 개발 우선 원칙: **설계 가이드를 파는 것보다 실제 업무를 끝내는 도구 1개를 입증하는 것이 중요하다.** 초보 사장님이 스스로 완료할 수 없는 제품은 저가여도 구매 가치가 약할 수 있다.

## 1. 현재 실제 제품 상태 — 근거/한계 분리 (2026-10-25 당시 관측)
- Private `hibi89/SMAX`의 **`frontend`** 개발 브랜치에는 ① 로컬 CSV 입력·사용자 확인 매핑·일자/금액 정규화·검토 상태·CSV 다운로드 관련 구현, ② 10종 **설계·교육용** 템플릿/규칙형 질문 가이드, ③ 단일 HTML 오프라인 SELF 빌더 및 Windows 개발자 QA 진입점이 보고되어 있다. 최신 실제 소스/HEAD를 다시 확인해야 한다.
- `backend`에서 **`node --test tests/csv-transform.test.mjs` 10/10 PASS** 실실행 근거. `frontend` 최신 **전체** `npm run qa:release`/HTML 생성 최종 실증은 완료로 보고되지 않았다.
- GitHub Actions 자체 시도는 **failure** 상태였고 단계/로그 확인 불가. 이유가 자동화 코드 결함인지 서비스 권한/runner인지 **미확인**. 브라우저 자동검증은 관리자 환경 차단으로 **E2E PASS 아님**, Windows Edge/Chrome 실제 고객동선 검증도 필요.
- `main`과 `frontend`는 다른 커밋을 가리킨다. 임시 홈페이지/브랜딩과 최신 SELF 패키징 소스는 **안전한 통합·회귀 검증 전 서로 동일한 출시판이 아님**. `site/` 유료 코어가 섞인 전체 사이트 공개 배포는 금지하고 `public-site/` 무료 소개/유료 SELF 패키지 분리를 유지한다.
- **실제 크몽 등록·거래·유료 고객·구매 후기·수익·다운로드/사용 지표·고객 효과 측정 = 검증된 증거 0.** 직원 교육, 고객사·공공기관 제휴 등 실적도 없음.
- 기술을 제품 수준으로 소개하는 기준은 `frontend/docs/KMONG_SELF_LISTING_DRAFT_20261025.md`의 정확한 제공범위, `frontend/STATUS.md` 최신 QA 증거, `frontend/HANDOFF.md`의 남은 작업을 따른다. 이 문서가 최신 개발 로그를 대체하지 않는다.

## 3. 경쟁우위 가설 (아직 시장검증 전)
- '누구나 AI를 쓴다'는 추상 문구보다 **'사장님 거래내역 CSV 정리·날짜·금액 확인·결과 다운로드'**처럼 구체적인 가치 제안이 더 시험하기 쉽다.
- **5만 원 SELF**는 과거 희망 판매가일 뿐 확정가·시장 적정가가 아니다. 실제 사용 편의성·고객지원 비용·크몽 수수료를 검토해야 한다.
- 낮은 비용의 대중화가 사명이라도 **가격만 낮추면 팔리는 것은 아니다**. 사용자의 시간절약/오류감소/직접 실행 가능성을 증명한다.
- 시장에서 소상공인의 AI 비용·숙련도 장벽이 있다는 방향은 유효한 가설이나 **조사 수치/시장 규모/경쟁사 가격은 출처·표본·조사시점을 확인해 별도 실사**. 미검증 숫자나 언론 인용을 공식 사업소개서에 확정 통계로 쓰지 않는다.

## 4. 실제 수요를 검증하는 최소 실험 (제안 목표, 완료 실적 아님)
**선행 게이트: 11/7 개발 결과가 제품 출고 검증을 통과해야 테스트 고객에 적용한다.** 출시·유료 등록은 창업자 별도 승인.

| 단계 | 제안 수치/방법 | 판단 기준 |
|---|---|---|
| A. 실동작 1종 | 실제 입력→확인→CSV 출력까지 합성 파일로 재현 | 도구 자체가 결과물을 생성하고, 위험 행을 보존하며, 회귀 테스트 통과 |
| B. 사용성 | 실제 타깃 사용자 **10명**에게 설명 없이 같은 업무 수행 요청 | 완료 비율·걸린 시간·중단 지점·지원 요청 횟수 기록. 편향된 지인만으로 일반화 금지 |
| C. 가치 | 기존 수작업과 비교 전/후 소요시간, 오류율, 재사용 의사 확인 | 재현 가능한 절약이 없다면 기능·타깃·설명을 수정 |
| D. 유료 의사 | 유효한 공식 판매 채널에서 **첫 유료 고객 3명** 확보 실험 | 실제 결제·환불·지원 비용·사용 성과를 측정. 3건은 초기 신호이지 시장 성공의 통계적 입증 아님 |
| E. 유지 가능성 | 4주 정도 총판매·환불·지원시간·재사용/추천의사 추적 | 건당 기여이익 양수이고 사용자 부담 없이 반복 운영 가능한가 |

**실패 판정 시 교정**
- 10명 중 대부분이 혼자 완료하지 못한다 → 디자인보다 **사용 절차/상품 범위·고객군**부터 줄이고 수정.
- 써보긴 하지만 결제하지 않는다 → 문제의 중요도·가치/가격·고객 분류·판매 메시지 검증. 무료 반응으로 매출을 추정하지 않음.
- 고객은 사지만 지원에 시간이 과도하다 → SELF 계약/제품 안내를 단순화하고 GUIDE 범위/가격을 다시 설계.
- 1종에서 수요가 확인되면 그 사용사례를 템플릿 확장 근거로 삼고, 수요가 없으면 **먼저 고객 문제를 재선정**. 단일 파일의 소표본으로 즉시 전체 사업 포기/성공 선언하지 않음.

## 5. 수익성 간단 역산 — 목표와 현실 구분
- **가정 가격 50,000원/건** 기준, 월 매출 **1,500,000원에 30건 / 2,000,000원에 40건**이 필요. 이는 **매출**이며 순수익 아님. 고객 수와 주문 건수는 같지 않을 수 있음.
- 건당 실제 기여이익 = 판매가 − 판매 플랫폼 수수료/정산 관련 비용 − 환불/결제 손실 − 변동 지원/운영 원가 (세금/고정비 고려 별도).
- 월 150~200만 원 **순수익** 목표라면 30~40건 **이상** 필요할 가능성이 크지만 정확한 건수는 실제 수수료·세금·비용을 넣어야 산정 가능. 반복 구매·업셀링은 현 상태에서 가정하지 않는다.
- 한 건당 1~2시간 지원이 필요해지는 순간 저가·1인 운영 모델이 쉽게 무너질 수 있으므로 **지원 시간**을 판매량과 같이 관리한다.
