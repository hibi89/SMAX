# SMAX 지능형 템플릿 검색 + 대화형 선택 UI 설계 (2026-10-25)

> 상태: 창업자 발상에서 출발한 **기술 설계 제안**, 검증/실코드/실서비스 없음. 목적은 사용자 입력이 정확한 템플릿 제목이 아니어도 관련 자동화 후보를 보여주는 것. **로컬 유료 LLM API 0원 원칙 유지**. `docs/SMAX_V1_EXECUTION_PLAN_20261025.md`의 업무 템플릿 기반 AX 표준화와 연결한다.

## 1. 창업자 요청과 가장 작은 구현 단위
- 대시보드에서 사장님이 `매일 메일로 오는 엑셀 폴더에 모으고 싶어`, `손님이 비슷한 질문 자꾸 해`처럼 **자연스러운 표현을 대충 입력**해도 업무 템플릿을 찾아 추천하는 **스마트 검색**을 제안.
- UI는 챗봇처럼 답하는 모양도 가능하지만, v1.0 핵심은 **규칙형 단계 안내 및 확인 질문**이지 LLM 자유대화가 아니다.
- 검색은 기존 카테고리 선택 방식을 **대체하는 선택지**로 추가한다. 매칭이 없거나 사용자 표현이 모호하면 수동 분류·질문 또는 무료 템플릿 요청 안내로 연결.

## 2. v1.0 추천 구현: 무AI API 검색 엔진
1. **템플릿 메타데이터**: `id`, `title`, `purpose`, `category`, `keywords`, `synonyms`, `exampleRequests`, `inputs`, `outputs`, `tools`, `difficulty`, `unsupported`, `version`, `validationStatus`.
2. **입력 전처리**: 한글/영어 띄어쓰기·대소문자·간단한 표기 차이·오타/부분 일치 감안. 소규모 v1.0은 사전·정규식·fuzzy match 중심으로 시작. 필요 시 한국어 형태소/토큰 처리 별도 추가.
3. **후보 검색**: 사용자 입력에서 목적어·도구·행동 힌트 추출(예: 이메일/첨부/엑셀/정리/저장). 제목 일치 + 템플릿 예시 문장/동의어 + 도구/입출력 필드 유사성의 **가중 점수**로 상위 3개 표시.
4. **추가 질문**: 최고 후보 점수가 충분하지 않거나 1·2순위가 비슷하면 `어떤 파일인가요?`, `출력은 로컬 폴더인가요, 시트인가요?`를 물어 재탐색. 임의 추측을 확정하지 않고 사용자가 템플릿/필드 매핑을 최종 승인.
5. **다음 단계 연결**: 선택한 템플릿을 로컬 AX 규칙 엔진에 전달 → 데이터 헤더/규칙 확인 → `AX_BLUEPRINT.json`, `DATA_SCHEMA.json`, `AI_BUILD_PROMPT.md`, `VALIDATION_CHECKLIST.md` 생성. 외부 도구 자동 설치/실행은 수행하지 않음.
6. **지원 범위 외**: 관련 템플릿이 없을 때 비슷한 다른 템플릿을 근거 없이 추천·실행하지 않고, `지원 템플릿 없음 → 신규 무료 제안` 경로로 안내.

## 3. UI 구상 (디자인은 사용자 주도)
- 상단 입력 힌트: **`무슨 일을 자동화하고 싶으세요? 편하게 적어보세요.`**.
- 예시 칩: `메일 엑셀 자동 저장`, `반복 문의 정리`, `회사 규정 검색`, `재고 보고서`.
- 검색 결과는 설명/지원 도구/필요 자료/난도/실제 검증 상태를 보여주는 상위 3개 카드.
- 1개 선택하면 **챗봇처럼 단계별 질문 → 결과 확인 → 데이터 매핑 → AI 구축 명령**. `유사도 점수`를 사용자에게 정확한 확률/정확도처럼 노출하지 않는다.
- 공식 Cloudflare 홈페이지에는 **공개 템플릿 설명 메타데이터만** 인덱싱하며, 로컬 프로그램의 고객 파일·민감정보는 브라우저 공개 사이트/서버로 전송하지 않는다. 같은 템플릿 카탈로그를 정적 파일로 빌드해 활용하되 미공개 업무지식·비공개 내부 정책의 자동 공개 금지.

## 4. AI 기술 분류와 단계 업그레이드
| 단계 | 기술 | 실제 AI 런타임 | 비용/제약 |
|---|---|---|---|
| 1차 v1.0 | 키워드 + 동의어 + 오타/유사도 랭킹 + 상태머신 질문 | **없음** | 정해진 유형·범위 내에서만 추론 |
| 2차 선택 | PC 내 로컬 임베딩/의미검색 모델 | **있음(로컬 추론)** | 유료 API는 0 가능하나 모델용량/CPU·메모리/라이선스 검증 |
| 3차 선택 | 로컬 또는 외부 LLM 자유대화/계획 | **있음** | 모델품질·성능/외부 비용·데이터 전송·보안 검증 필수 |

- GPT-6가 규칙을 작성했다는 사실은 **'AI를 개발 도구로 사용'**했다는 뜻이지, 완성품이 고객 요청에서 AI 추론을 실행한다는 뜻은 아니다.
- 템플릿별 예시 문구·동의어 데이터를 GPT가 생성했더라도 제품 동작은 **고전적 검색/규칙 실행**.
- 문서 RAG(검색증강생성)와 규칙형 템플릿 검색은 구별. 후자는 생성형 언어모델 없이도 가능.

## 5. 검증/릴리스 기준
- **최초 10종**에 대해 템플릿별 5개 이상의 말투/오타/비유·부정/유사 요청 **합성 테스트**를 마련. 단일 사용자가 만든 시나리오라 실제 고객 분포의 성공률을 대표하진 않음.
- **긍정 테스트**: `메일로 엑셀 오면 저장`→이메일 첨부, `반복 고객 질문`→FAQ, `직원들이 내규 찾아 묻는 거`→RAG 설계. 유사도/랭킹은 개발 후 수치화.
- **안전 테스트**: `계좌로 돈 자동 송금해` 등 범위 밖/고위험 요청은 `지원불가/추가 설명`으로 처리; 잘못된 템플릿에 임의로 끼워 맞추지 않음.
- **사용자 수동 변경**: 추천을 받아도 최종 템플릿과 열 매핑은 사용자가 검수·확인. 검색 품질 부족이 잘못된 자동화를 유도하지 않게 한다.
- 50/100/1000종 확장 시 새 템플릿이 기존 검색 결과를 망가뜨리는 **회귀 평가셋**과 버전별 품질 기록. 검색랭킹에 통계적 의미 없는 % 정확도 표시 금지.

## 6. 시간·역할·착수
- **P1 공통 계약**에 검색 필드를 추가하고 **P2 엔진**에 템플릿 매처를 포함하는 범위로 제안. 14일 개발 하드리밋 유지. v1.0이 초과 위험이면 키워드/동의어 우선, 로컬 임베딩 모델은 이후 버전.
- 사용자: 대시보드 검색창/질문 UI/추천 카드·튜토리얼 프론트엔드 구성.
- GPT-6: 검색 인덱스/한국어 동의어/후보 랭커·질문 상태머신·로컬 테스트·입출력 계약.
- 아직 실제 제품 소스/검증 결과가 없는 **기획 단계**. 공개 배포/실고객 입력 수집/유료 API/개인정보 처리 등의 추가 행동은 별도 승인.
