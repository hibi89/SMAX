## 14 집중개발일 MVP 검증 목표
| 집중일 | 개발 작업 | 인수 기준 |
|---|---|---|
| D1–D2 | 합성 업무 설명 10개와 정답 룰 수립 | 고객 정보 없이 공개 가능한 fixture |
| D3–D5 | 자연어→후보 업무 JSON 변환 | 스키마를 만족하거나 누락 질문, 환각으로 쓰기 권한 생성 금지 |
| D6–D7 | 업무 규칙·예외·출처·모순 검증 | 실패 사유/확인 질문 재현 |
| D8–D10 | 파일 기반 변환·보고 모듈의 dry-run | 외부 쓰기 없이 결과 샘플/검증 로그 |
| D11–D12 | 최소 웹 인터페이스 | 입력·후보 규칙·수정·승인 단계 노출 |
| D13–D14 | 오류·보안·비용 한도 테스트 | 적어도 20개의 정상/적대적 케이스와 미충족 게이트 기록 |

**2주=검증 목표, 4주=제한적 작동 MVP 가설, 6~10주=유료 파일럿 시도 가설.** 이 기간을 상용 완제품/계약 보장으로 혼동하지 않는다.

## 사업 단계
- Gate G0: 발주공고 근거와 3개 업무 후보 비교, 하나 선택.
- Gate G1: 10/10 합성 업무에서 예상 정형 모델 또는 명시적 누락 질문 생성.
- Gate G2: 처리 불가 모듈/다른 기업 데이터/무승인 외부 쓰기 100% 거부; dry-run 합격.
- Gate G3: 첫 타깃 잠재 고객 10개사의 실제 문제 검증, 3개사의 유료 시험 의향.
- Gate G4: 안전한 제한 유료 기능 및 가격·계약·정기 요금 확인.
- Gate G5: 첫 실제 99,000원 결제와 환불·원가·지원 기록 확인.
- Gate G6: 반복 구매/구독·파트너 판매 검증 후 확장.
