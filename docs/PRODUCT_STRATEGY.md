# SMAX 제품 전략 — 제품 정의 및 기술 단계

## 핵심 제품 정의
SMAX = **Self-Made AX Platform**.
"기업이 자신의 기존 업무를 자연어·문서·데이터로 설명하면 AI가 공통 업무 패턴에 맞게 표준화하고, 필요한 확인 질문을 제시한 뒤 승인된 표준 모듈로 자동화를 구성하며, 미래 AX 기능을 확장할 수 있게 만드는 셀프서비스 SaaS."

> 업무를 고객마다 제멋대로 맞춰 개발하는 SI/대행사가 아니다. 지원된 표준 흐름과 설정 가능한 예외만 상품 범위에 포함한다. '우리 방식 그대로 전부' 요구에는 범위를 공개하고 부적합 시 구매를 권장하지 않는다.

## 구상의 출발점: '프로그램 안에서 사고하는 AI'
- 단순 RAG: 외부 문서 검색/증강으로 질문에 답하는 구성 요소.
- SMAX 핵심: 업무 제약·스키마·허용 모듈·회사 규칙을 바탕으로 **LLM의 출력 제약, 도메인별 규칙 엔진, 계획 검사, 질문/승인 로직을 결합**.
- 모델의 은닉된 실제 chain of thought를 내부적으로 고정·열람하는 개념은 아님. 추론 **결과물과 실행 권한**을 통제한다.
- 인간 업무 공통 패턴: 입력→분류→검증→조건 판단→승인→처리→출력→감사기록. 업종별 차이는 설정값/템플릿으로 흡수.
- 고객이 원하는 것은 AI와 대화 그 자체보다 '자료 넣고 안전하게 결과까지'의 실용적 업무 가치.

## 전체 구조
1. Intake — 자연어, 스프레드시트, 문서, 기존 처리 규칙·예시.
2. Reasoning — 업무 액터·순서·규칙·예외·데이터 스키마·책임자 추출. 빈칸에 대해 재질문.
3. Normalization — 회사 규칙을 SMAX 범용 데이터 계약에 맵핑.
4. Verification — 누락·모순·권한·데이터 출처·허용 노드 검사, 의사결정 근거 노출.
5. Consent — 고객 담당자의 명시적 승인/수정.
6. Composer — CSV·엑셀·리포트·조건분기·승인 등 제한된 모듈의 조합.
7. Dry-run — 차이점·결과 미리보기, 실패·중복·쿼터 제어.
8. Runtime — 충분히 검증된 구간만 운영. 비승인 쓰기/금전 거래 금지.
9. Trace — 실행 내역과 사용자에게 표시하는 판단 근거/데이터 출처/변경 이력.

## 기술 단계
- P0: 구조화된 JSON 업무 계획 유효성 검사기 (로컬 시제품; GitHub 원격 미반영).
- P1: 자연어/합성 문서→업무규칙 후보, 누락 질문, 신뢰 한계 명시.
- P2: 승인된 규칙의 표준 업무 플로우+드라이런.
- P3: 1개 타깃 업무/업종 웹 데모와 사용량 통제, 고객 시험.
- P4: 유료/고객 분리/보안/구독.
- P5: 재판매 파트너 + 업종 템플릿/통합.
- 장기: 폭넓은 셀프서비스 AX 플랫폼. 초기 MVP와 동일시하지 않음.

## 첫 대상 선정 원칙
시장 공고를 광범위하게 조사하되 **초기 구현은 하나**. 가설 후보:
A. 도소매/유통의 주문서·명세서·견적 데이터 정리/비교.
B. 제조/구매의 발주·입고·정산 전 데이터 대사/오류 검사.
C. 전문 서비스 회사의 고객 요청 분류·정리·진행 보고.
수요의 객관적 순위는 아직 조사 불충분. 공고 예산=실제 계약/판매 증거가 아님.

## 처음부터 제외
- 고객별 임의 코딩과 사내 전용 복잡한 ERP 완전 연동.
- ERP 수정/계좌 이체·세금계산서 전송 등 위험한 실제 외부 쓰기를 무승인 자동화.
- 임의 shell/Python 코드의 AI 자율 실행.
- 기밀 실고객 데이터를 무료 AI 모델에 그대로 입력.
- AI 판단 정확도 보장·법적 컴플라이언스 자동 보증.

## 2026-10-25 정체성 재확인 — AX 준비 인프라가 중심
- 고객 = AX 변화 필요성을 인식하지만 큰 투자와 조직 변경이 부담스러운 소기업·자영업 사장님. 상품 = **저렴한 연간형 셀프 AX 준비 경험**과 발전된 미래 AI가 읽고 활용하기 좋은 업무·데이터·규칙/권한 **표준 기반**.
- 특정 업무 자동화는 AX 기반을 시연하는 **예제 또는 선택 모듈**이고 제품의 정체성이 아니다. 2026-10-25 조사에서 발주↔명세서 대사(B)를 우선 제안했으나 사용자 창업 구상은 **B 단일 기능 제품과 다름**. 사용자 방향을 우선.
- 초기 결과물은 업체 업무 지도, 소스가 추적되는 데이터/절차 구조, 규칙·모호점 명세, AX 준비 갭/우선순위, 수정/내보내기. 실제 자동화·직원 대체 효과와 AI 미래 호환성을 무조건 보증하지 않는다.
- 구현은 지원 범위가 제한된 공통 구조부터 시작하되 고객마다 새로운 코드를 개발하지 않는다. 테스트용 업종/사례 선택과 특정 업종 전용 SaaS 사업으로의 전환을 혼동하지 않는다.
- 복제 리스크보다 원가·사용 편의성·신뢰·지속 갱신·추천 기반 유통에 집중. 온라인 '동네 단골집'은 브랜드 관계 비유이며 지역 영업 의무가 아니다.

## 2026-10-25 우선 적용: 고객 PC 로컬 실행
- **사용자 신규 확정:** 온라인 판매하더라도 실제 SMAX 프로그램은 **고객 PC에서 로컬로 실행**한다. 기존 문서의 '클라우드 SaaS 우선/서버별 tenant와 월 AI 크레딧' 설계보다 이 의사가 우선. 웹사이트는 유입·소개·구매·다운로드용이며 처리 엔진 호스팅이 핵심 아님.
- 실제 고객 업무·파일은 원칙적으로 고객 PC에서 파싱·구조화·검증·결과 저장. **필수 외부 LLM/API 호출 0**으로 설계. 고객 PC 내 복구/백업·파일삭제/수정 위험은 안내.
- 기본 분류는 인터랙티브 문답/업무 카테고리 선택 + 사전에 정의한 공통 업무 패턴 + 파일 헤더/타입 인식 + 규칙 검증. 복잡한 자연어·임의 문서의 의미 해석은 **보장 불가**하며 애매하면 질문/확인필요로 반환; 추정 자동 확정 금지.
- 생성 결과: 업무맵, 열/자료 스키마, 업무 룰·예외·근거, AX 준비 갭, JSON/CSV/Markdown 등 내보내기. 모델·기술 변화에 대한 미래 완전 호환을 보증하지 않는다.
- 로컬 구현 후보 비교: (A) 브라우저 정적 HTML/JS 오프라인 파일 기반 — 저원가·수정 빠름, file://와 보안/호환 제한 검증 필요; (B) 데스크톱 번들형(WebView/Tauri 등) — 실행 편의성/파일 통제 유리, 빌드·서명·배포/오탐 부담. 선택·실제 구현은 별도 승인.
- 로컬 유료 판매에는 인터넷 상시 인증/토큰 서버가 필수가 아니고 완전한 연간 사용 만료 통제도 어려움. 라이선스/갱신/업데이트/기기 호환 약속은 구체적으로 시험 후 고지.

## 2026-10-25 현재 상품 정의 우선순위: SELF / GUIDE / WEB
- 본문의 초기 SaaS/LLM 추론/연간 99,000원 논의는 **과거 구상**. 현재 1차는 **SELF**: 고객 PC 오프라인 규칙·업무 템플릿/CSV/안전 질의/AX 설계·외부 AI 구축 안내. 중간 결과를 정형 데이터로 내보내는 것 외에 **검증된 로컬 완성형 변환/보고 1~2종**을 제한적으로 추진. 자체 유료 AI API 필요 없음. SELF 5만원 희망가.
- **GUIDE**: 선택 +5만원 제한된 비동기 문자 코칭; 고객별 실구축·계정접속·자료 수신은 제공하지 않음.
- **WEB(후속 유료 실행형)**: 업무 템플릿마다 실제 입력→처리→결과가 웹 브라우저에서 끝나는 사례만 검증해 고객 계정에 템플릿별 유료 이용권 제공. 구매자 권한은 반드시 서버에서 검사하고 유료 코어 소스의 공개 정적 배포를 금지. 현재는 WEB 기능/로그인/유료결제 **미개발·미판매**이며 도메인/배포/고객 데이터 서버수집 승인도 없음.
- 표준화 템플릿 계약·데이터 검증 코어·출력 포맷은 SELF와 미래 WEB이 재사용하도록 설계. 하지만 인증/서버 실행·서비스별 OAuth는 재사용만으로 자동 구현되지 않음. WEB은 1차 개발 14달력일 범위 밖.
- 제품명 `SMAX Square / 스맥스스퀘어 / SMAX²`는 **상표 확인 전 후보명**. 공식 출시 명칭 확정/상표출원 완료로 오해 금지.
- 최신 상세: `docs/SELF_WEB_ROADMAP_20261025.md`. 1차 개발 시작 2026-10-25, 종료 상한 2026-11-07.
